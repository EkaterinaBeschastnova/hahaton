# «Мой дом» — мини-приложение и чат-бот для MAX

## Назначение решения

«Мой дом» — MVP единого цифрового кабинета жителя многоквартирного дома. Решение объединяет мини-приложение и чат-бот в MAX и помогает:

- видеть важные события, новости и работы по дому;
- передавать показания счётчиков и просматривать историю;
- создавать индивидуальные заявки и присоединяться к коллективным;
- отслеживать приоритет и состояние заявок;
- получать сводку по дому, квитанциям, работам и контактам;
- переходить из чат-бота в мини-приложение без поиска отдельной ссылки.

Работающая версия мини-приложения: <https://moi-dom-max-katerina3255345.amvera.io/>

## Основной пользовательский сценарий

1. Пользователь открывает чат-бот в MAX и отправляет `/start`.
2. Если пользователь ещё не зарегистрирован, бот предлагает формальную регистрацию.
3. После регистрации бот подтверждает её и показывает кнопку **«Открыть Мой дом»**.
4. Пользователь открывает мини-приложение, выбирает или добавляет дом.
5. На главной странице он видит важные события и действия на сегодня.
6. Внутри дома пользователь передаёт показания, просматривает новости и работы, создаёт заявку или присоединяется к коллективной заявке.
7. Созданная через бот заявка сохраняется в общей базе и появляется в мини-приложении.
8. В чат-боте пользователь может запросить сводку по выбранному дому.

## Состав и архитектура решения

```text
MAX / обычный браузер
        |
        v
React 19 + TypeScript + Vite
        |  HTTP / JSON
        v
FastAPI + SQLAlchemy async
        |
        v
SQLite (/data/mydom.db)

Отдельный процесс в том же контейнере:
MAX Bot long polling -> MAX Platform API
                     -> общая SQLite
```

Состав репозитория:

- `frontend/` — React-интерфейс мини-приложения;
- `backend/app/main.py` — REST API и раздача собранного frontend;
- `backend/app/bot.py` — long polling чат-бота MAX;
- `backend/app/models.py` — модель данных SQLAlchemy;
- `backend/app/seed.py` — идемпотентные тестовые данные;
- `backend/app/services/` — бизнес-логика домов и вычисление их состояния;
- `Dockerfile` — воспроизводимая multi-stage сборка frontend и backend;
- `compose.yaml` — единая точка локального запуска;
- `amvera.yml` — конфигурация работающего публичного развертывания.

Статус дома не хранится отдельной вручную изменяемой строкой. Он вычисляется из активных событий, заявок, сроков передачи показаний и ремонтов. Все сущности дома связаны по `building_id`.

## Быстрый запуск через Docker

Требуется Docker Desktop или Docker Engine с плагином Docker Compose.

Единственная команда для сборки и запуска всех локальных компонентов:

```bash
docker compose up --build
```

После запуска:

- мини-приложение: <http://localhost:8080/>;
- проверка API: <http://localhost:8080/health>;
- интерактивная документация API: <http://localhost:8080/docs>.

Без `MAX_BOT_TOKEN` сайт и API полностью запускаются, а процесс бота завершает работу с понятным сообщением в логе. Для локальной проверки интеграции MAX создайте `.env` по шаблону ниже.

## Параметры и переменные окружения

Скопируйте `.env.example` в `.env` и при необходимости измените значения:

```bash
cp .env.example .env
```

В Windows PowerShell:

```powershell
Copy-Item .env.example .env
```

| Переменная | Обязательность | Значение по умолчанию | Назначение |
|---|---:|---|---|
| `APP_PORT` | нет | `8080` | Порт приложения на хосте |
| `DATABASE_URL` | нет | `sqlite+aiosqlite:////data/mydom.db` | Строка подключения к БД |
| `MAX_API_URL` | нет | `https://platform-api2.max.ru` | API платформы MAX |
| `MAX_BOT_TOKEN` | для проверки бота | пусто | Токен чат-бота MAX |
| `MINI_APP_URL` | для кнопки в MAX | `http://localhost:8080` | Адрес, который открывает кнопка бота |
| `WEBHOOK_SECRET` | для публичного запуска | тестовое значение | Проверка входящих служебных запросов |
| `JWT_SECRET` | для публичного запуска | тестовое значение | Подпись локальных JWT |

Рабочие токены, ключи и пароли нельзя добавлять в Git. Файл `.env` исключён из Docker-контекста и должен храниться только локально или в секретах платформы развертывания.

## Используемые порты

| Порт | Где используется | Назначение |
|---:|---|---|
| `8080` | контейнер и хост по умолчанию | Web-интерфейс, REST API и статические файлы |

Vite и Node.js используются только на стадии сборки Docker-образа и не открывают отдельный порт во время работы контейнера.

## Зависимости

Backend использует Python 3.11. Версии библиотек зафиксированы в `backend/requirements.txt`:

- FastAPI и Uvicorn;
- SQLAlchemy и aiosqlite;
- pydantic-settings;
- httpx;
- PyJWT;
- python-multipart;
- truststore.

Frontend собирается на Node.js 22. Полный граф версий зафиксирован в `frontend/package-lock.json`. Основные зависимости указаны в `frontend/package.json`: React 19, React DOM, TypeScript и Vite.

Сборка multi-stage: Node.js нужен только для `npm ci` и `npm run build`, после чего в итоговый Python-образ копируется только каталог `dist`. Это сокращает размер образа и время повторной сборки. При наличии кэша Docker сборка укладывается в установленное ограничение; первая загрузка базовых образов в это время не входит.

## Внешние сервисы и интеграции

### MAX Platform API

MAX — единственный внешний сервис, который нельзя воспроизвести внутри Docker. Он нужен для:

- получения команд и callback-событий чат-ботом;
- отправки сообщений и интерактивных кнопок;
- получения `initData` при открытии мини-приложения внутри MAX;
- перехода по кнопке из бота в публичное мини-приложение.

Условия проверки MAX-интеграции:

1. действующий бот, созданный в MAX;
2. его токен в `MAX_BOT_TOKEN`;
3. исходящий HTTPS-доступ контейнера к `https://platform-api2.max.ru`;
4. публичный HTTPS-адрес мини-приложения в `MINI_APP_URL`;
5. только один активный long-polling процесс с одним токеном.

Нельзя одновременно запускать облачный и локальный экземпляры бота с одним токеном: они будут конкурировать за события. Для локального теста бота остановите облачный процесс или используйте отдельного тестового бота. Для проверки интерфейса это не требуется — используйте браузер и демо-вход.

Публичный MVP размещён в Amvera и должен оставаться запущенным независимо от локального Docker: <https://moi-dom-max-katerina3255345.amvera.io/>.

## Работа с данными

Основное хранилище MVP — SQLite. Файл БД находится в именованном Docker volume `mydom_data` по пути `/data/mydom.db`, поэтому обычная остановка или пересборка контейнера не удаляет данные.

Основные сущности:

- пользователи и регистрации мини-приложения;
- дома и профили домов;
- связь жителя с домом;
- счётчики и переданные показания;
- события и новости;
- индивидуальные и коллективные заявки, участники заявок;
- работы и ремонты;
- уведомления и подписки.

Frontend обращается к API по относительному пути `/api`, поэтому при локальном и облачном запуске дополнительная настройка адреса backend не нужна. Авторизация демо-режима использует JWT, а выбранный аккаунт сохраняется в `localStorage` браузера.

## Тестовые данные

При первом старте FastAPI создаёт таблицы и выполняет `seed_demo_data()`. Seed идемпотентный: повторный запуск не должен дублировать дома, события и заявки.

Для обычного повторного запуска тестовые данные сохраняются:

```bash
docker compose down
docker compose up
```

Для полного сброса локальной БД и повторного создания исходных тестовых данных:

```bash
docker compose down -v
docker compose up --build
```

Команда `down -v` удаляет только именованный Docker volume данного Compose-проекта. Используйте её осознанно: созданные локально заявки и показания будут удалены.

## Пошаговый сценарий проверки

### Локальная проверка мини-приложения

1. Выполнить `docker compose up --build`.
2. Дождаться строки Uvicorn о запуске на `0.0.0.0:8080`.
3. Открыть <http://localhost:8080/health> и убедиться, что возвращается `{"status":"ok","version":"0.2.0"}`.
4. Открыть <http://localhost:8080/>.
5. Пройти формальную регистрацию через демо-форму.
6. Убедиться, что на главной странице отображаются дома, важные события и блок «Нужно сделать».
7. Открыть дом и проверить новости, события, заявки, счётчики, работы и контакты.
8. Передать тестовое показание и убедиться, что оно появилось в истории и на графике.
9. Создать заявку и убедиться, что новая заявка находится выше выполненных.
10. Открыть коллективную заявку и присоединиться к ней.
11. Обновить страницу: аккаунт и внесённые данные должны сохраниться.

### Проверка чат-бота MAX

1. Указать `MAX_BOT_TOKEN` и публичный `MINI_APP_URL` в `.env` либо использовать уже развернутый экземпляр.
2. Убедиться, что с этим токеном работает только один экземпляр бота.
3. Запустить решение и отправить боту `/start`.
4. Для нового пользователя нажать кнопку регистрации.
5. Получить сообщение «Спасибо, что вы зарегистрировались!» и кнопку **«Открыть Мой дом»**.
6. Проверить кнопку **«Сводка по дому»**: выбрать дом, затем раздел ЖКХ, квитанций, работ или контактов.
7. Создать заявку через бот.
8. Открыть мини-приложение и убедиться, что заявка отображается у выбранного дома.

## Примеры ожидаемого поведения

- `GET /health` возвращает HTTP 200 и статус `ok`.
- Без токена MAX web-приложение работает, а в логах появляется `MAX_BOT_TOKEN не найден`.
- Повторный запуск не создаёт дубликаты тестовых домов.
- После регистрации бот возвращает подтверждение и HTTPS-кнопку мини-приложения.
- Новая заявка располагается перед выполненными заявками.
- Присоединение к коллективной заявке увеличивает число участников без создания дубликата заявки.
- Переданное показание сохраняется и используется в истории/графике.
- Важное событие можно закрыть в сводке, не удаляя сам факт события из данных дома.
- Если отправка уведомления в MAX временно недоступна, основная запись сохраняется в БД.

## Известные ограничения MVP

- SQLite подходит для демонстрации и одного экземпляра приложения, но не рассчитан на горизонтальное масштабирование и большую конкурентную нагрузку.
- Регистрация и авторизация через Госуслуги представлены демонстрационным сценарием без продуктивного OAuth.
- Часть контактов, новостей, изображений, квитанций и показаний является тестовой.
- Нет промышленного разграничения прав управляющей компании и жителей.
- Бот использует long polling; один токен должен обслуживаться одним процессом.
- Локальный `http://localhost` недоступен с другого устройства и не подходит для кнопки Mini App в MAX — требуется публичный HTTPS-адрес.
- Для демонстрационного размещения параметры и база находятся в инфраструктуре Amvera; доступность зависит от состояния внешней платформы.

## Остановка и повторный запуск

Остановить контейнеры, сохранив данные:

```bash
docker compose down
```

Повторно запустить существующую сборку:

```bash
docker compose up
```

Пересобрать после изменения исходного кода:

```bash
docker compose up --build
```

Запустить в фоне:

```bash
docker compose up --build -d
```

Посмотреть логи:

```bash
docker compose logs -f
```

Полностью остановить и удалить локальные тестовые данные:

```bash
docker compose down -v
```
