# Мой дом — backend v2

## Модель данных

`buildings` — стабильная запись дома.

Всё динамическое хранится отдельно и связано внешним ключом `building_id`:

- `building_profiles` — характеристики здания;
- `meters` — приборы учёта и необходимость передачи показаний;
- `building_events` — отключения, объявления, аварии, работы;
- `requests` — заявки жителей;
- `repairs` — плановые и капитальные ремонты;
- `resident_buildings` — какие дома принадлежат пользователю;
- `resident_building_meta` — роль пользователя в доме.

## Состояние дома

У дома нет вручную записанного `status = urgent/ok`.

`app/services/building_state.py` вычисляет состояние из фактов:

- активное срочное событие/ремонт -> `urgent`;
- показания пора передать -> `attention`;
- плановое важное отключение -> `attention`;
- активная заявка/проблема -> `attention`;
- значимый ремонт -> `attention`;
- причин нет -> `level = null`.

Поэтому статус не может разойтись с содержимым дома.

## API

- `GET /api/houses/catalog` — лёгкий каталог домов;
- `GET /api/houses/my` — полные данные домов пользователя;
- `GET /api/houses/{id}` — один дом со всеми дочерними данными;
- `POST /api/houses/{id}/join` — привязать дом к пользователю;
- `POST /api/houses/{id}/meters/{meter_id}/submit` — передать показания;
- `GET /api/houses/{id}/requests` — заявки конкретного дома;
- `POST /api/requests` — создать заявку с `building_id`.

Seed запускается автоматически и не создаёт дубли.
